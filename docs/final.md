## 0. 공동 편집 규칙

이 파일은 Claude와 GPT가 동시에 편집한다. 공동 검토 후의 구현 기준은 이 파일로 통일하고, 원안 문서는 검토 이력으로 보존한다.

1. **편집 직전에 파일을 다시 읽는다.** 읽은 뒤 바뀌었으면 최신 내용 위에서 고친다. 파일 전체를 덮어쓰지 말고, 필요한 부분만 고친다.
2. 상대가 쓴 내용을 말없이 지우지 않는다. 반대 의견이 있으면 **13절 검토 기록**에 `[Claude]` 또는 `[GPT]` 태그를 붙여 남긴다. 합의되면 본문에 반영하고, 그 기록에 `→ 반영`이라고 적는다.
3. 결정을 바꿀 때는 1절 결정 표와 해당 본문을 함께 고친다.
4. 사실 관계(현재 코드 동작)는 파일과 줄 번호를 근거로 적는다.

## 3. 1단계: 모바일 입력 방식

### 3.1 상태별 동작

| 상태 | 탭 | 손가락으로 밀기 | 도구 표시 |
|---|---|---|---|
| 기본 | 한 칸 선택·해제 | 페이지 스크롤 | `여러 칸 선택` 버튼 |
| 여러 칸 선택 | 한 칸 선택·해제 | 여러 칸 선택·해제(드래그) | `선택 완료` 버튼 + "선택 모드" 표시 |
| 읽기 전용 히트맵 | 그 칸의 참여자 표시(기존) | 페이지 스크롤 | 버튼 없음 |

- 적용 대상: 참가자 응답 시간표(`Grid`, 칠하기 가능)와 날짜 모드 달력(`DateGrid`, 칠하기 가능).
- 선택된 칸에서 드래그를 시작하면 그 범위를 해제한다(기존 규칙 유지).
- 변경 내용은 탭이나 드래그를 마칠 때 자동 저장한다. `선택 완료`는 모드를 끄는 버튼일 뿐이다. 저장 버튼으로 오해하지 않도록 옆에 `저장 중… / 저장됨`을 함께 보여 준다.
- 선택 모드는 이벤트 페이지를 떠나거나 새로고침하면 기본 상태로 돌아간다.

### 3.2 기본 상태: 탭과 스크롤 구분
- 터치 리스너가 `preventDefault()`를 하지 않는다. 칸의 `touch-action`은 `manipulation`(이동 허용, 더블탭 확대 차단)으로 바꾼다.
- **기본 상태의 한 칸 선택은 브라우저 `click`을 주 경로로 사용한다.** 스크롤·취소 뒤 호환 클릭이 오더라도 선택하지 않도록 검증한다. 마우스·펜 드래그나 선택 모드에서 이미 처리한 입력의 후속 클릭도 중복 저장하지 않는다. DateGrid의 기존 클릭 억제가 기본 모드의 정상 터치 탭까지 막지 않도록 처리한다.
- 터치를 시작했다는 이유만으로 응답을 바꾸지 않는다. 스크롤로 시작한 손동작은 손을 뗄 때까지 선택으로 바뀌지 않는다.

### 3.3 선택 모드: 드래그
- 기존 iOS 수정 로직(non-passive 네이티브 터치 이벤트, `touchstart`에서 `preventDefault`)을 **선택 모드일 때만** 켠다. 덕분에 `59e5108`·`dbd364f` 동작을 그대로 쓴다.
- 선택 모드에서는 기존처럼 기본 동작을 차단하고, 호환 `click`이나 마우스 이벤트가 뒤따르더라도 이미 처리한 선택을 다시 토글하지 않는다.
- 터치에서 파생된 `pointercancel`과 실제 `touchcancel`을 구분한다(기존 iOS 이슈).
- **취소 처리 변경**:
  - 정상적으로 손을 떼면 마지막 칸까지 저장한다. 렌더링 시점과 상관없이 저장되어야 한다.
  - 실제 `touchcancel`, 두 번째 손가락, 모드 종료, 날짜 페이지 변경이 일어나면 이번 드래그만 취소하고 드래그 시작 전 상태로 돌아간다. 그 전에 끝낸 선택은 유지한다.
  - 지금 코드의 "`touchcancel`이면 저장"은 바꾼다.

### 3.4 도구 위치와 입력 장치
- 버튼과 저장 상태는 편집 중인 시간표 위쪽에 둔다. 시간표를 보는 동안 계속 닿도록 편집 영역 안에서 `position: sticky; top: 0`으로 고정하고, 320px·글자 확대에서는 한 줄을 강제하지 않고 줄바꿈을 허용한다. 머리글 고정 위치는 도구 바의 실제 높이에 맞춘다.
- 버튼을 보일지는 `pointer: coarse` 하나로 정하지 않는다. `any-pointer: coarse` 또는 `navigator.maxTouchPoints > 0`이면 보여 준다. 터치와 마우스를 같이 쓰는 기기를 지원하기 위해서다.
- PC 마우스·펜 드래그는 선택 모드와 상관없이 지금처럼 바로 동작한다.
- 안내 문구(터치 기기만): "탭: 한 칸 선택 · 여러 칸은 `여러 칸 선택`을 켜고 드래그"

| 날짜 이동 | `이전 날짜` / `다음 날짜` 버튼. "3–5일 / 전체 7일"처럼 현재 범위와 전체 수를 표시하고, 처음과 끝 페이지에서는 해당 버튼을 비활성화 |
| 날짜 모드 달력 | 기존 월별 7열 달력 유지(현재 **최소 높이** 58px, 너비는 7열 분할). 56px 하한은 적용하지 않고, 320px에서 7열이 들어오도록 여백만 조정 |
| 참가자·관리자 히트맵 | 시간표와 같은 날짜 나눠 보기 적용 |
| PC(터치 아님) | 지금 크기 유지. 날짜가 많아 넘칠 때만 나눠 보기 |

### 4.2 선택 유지와 화면 전환
- 날짜를 넘겨도 안 보이는 날짜의 선택까지 모두 유지한다. 응답 상태는 페이지가 아니라 이벤트 단위로 관리하며, 저장 배열을 현재 페이지로 잘라 보내지 않는다.
- 화면 회전이나 크기 변경으로 한 페이지 날짜 수가 바뀌면, 보고 있던 첫 날짜가 계속 화면 안에 남게 다시 계산한다. 드래그 중 날짜 열 재배치가 필요하면 이번 드래그를 취소해 시작 전 상태로 복귀한 뒤 계산한다. 주소창에 따른 화면 높이 변화만으로는 불필요하게 취소하지 않는다.
- 드래그 중에는 날짜 페이지를 자동으로 넘기지 않는다. 여러 페이지에 걸친 드래그는 지원하지 않는다.
- 관리자 결과표에서 날짜·시간을 누르면 그 날짜가 있는 페이지로 이동한 뒤 강조한다(기존 강조 기능 확장).

### 4.3 스크롤 구조
- 표 안에는 세로 스크롤도 가로 스크롤도 두지 않는다. 세로는 페이지 전체가 늘어나고, 페이지 전체의 가로 넘침도 만들지 않는다.
- 나눠 보기에서는 `.grid-wrap`의 불필요한 스크롤 컨테이너를 제거하고 날짜 머리글을 편집 영역 안에서 sticky로 유지한다. 조상 overflow·레이아웃과 도구 바의 실제 높이를 함께 검증한다. overflow 하나를 제거한 것만으로 모든 브라우저에서 고정이 보장된다고 판단하지 않는다.
- 결과표는 기존처럼 결과 행 수만큼 자연스럽게 길어진다.

### 4.4 터치 대상과 글자 크기 (QA b)
- 터치 기기의 일반 조작 버튼은 최소 44×44px를 목표로 한다. 시간표 칸은 4.1의 56×32px 초기값으로 별도 검증하고, 7열 달력에는 44px 너비를 일괄 강제하지 않는다. QA가 잰 작은 요소: 로그아웃 링크 52×23px, 달력 이전/다음 버튼 27×29px. 새로 만드는 `여러 칸 선택`·`이전/다음 날짜` 버튼도 이 기준을 따른다.
- 모바일에서 시간·요일 라벨(지금 12px)은 14px 안팎으로 키운다. 날짜 열 최소 너비 56px 안에 들어가는지 함께 확인한다.

## 5. 1단계: 칠하는 중 화면 끝 자동 스크롤

### 5.1 동작
- 선택 모드에서 실제로 드래그하는 중에만 작동한다. 기본 상태, 단순 탭, 읽기 전용 히트맵에서는 작동하지 않는다.
- 상단은 고정 도구 바·머리글 아래의 유효 선택 영역 경계, 하단은 visual viewport 하단을 기준으로 약 40px 구간에 들어오면 `window`를 세로로 스크롤한다. 경계에 가까울수록 빨라지되 상한을 둔다. 범위와 속도는 실기기에서 조정한다.
- `requestAnimationFrame`으로 돌린다. 손가락이 멈춰 있어도 화면이 움직이면 손가락 아래 칸을 다시 계산해서 선택을 이어 간다.
- 지금 편집 중인 영역 안에서만 칠한다. 시간 모드는 현재 날짜 페이지의 표 끝에서 멈춘다. 날짜 모드는 이벤트의 월별 달력 전체를 한 영역으로 보고 다음 달까지 선택을 이어갈 수 있지만 다른 패널로 넘어가지 않는다. 위쪽 경계는 고정 도구 바·머리글을 제외한 실제 선택 영역을 기준으로 한다.
- 가로 방향 자동 스크롤과 페이지 자동 넘김은 없다(4.2).

### 5.2 멈추는 조건
손을 뗄 때, 실제 `touchcancel`, 두 번째 손가락, 페이지 이탈(`visibilitychange`, `blur`), 선택 모드 종료, 날짜 페이지 변경, 날짜 열 재배치가 필요한 화면 회전·너비 변경. 저장과 취소 규칙은 3.3을 따른다.

## 6. 2단계: 이벤트 생성 규칙과 문구

### 6.1 날짜·시간 입력

| 항목 | 동작 |
|---|---|
| 과거 날짜 | **새 이벤트 생성 때만** 막는다. 시간·날짜 두 모드 모두 |
| 화면 | 시간 모드 달력의 지난 날짜는 `disabled`, 날짜 모드 범위 입력에는 `min=오늘` |
| 서버 | `POST /api/events`에서 이벤트 시간대 기준 오늘보다 이른 날짜가 있으면 400. 날짜를 몰래 빼지 않고 오류로 알린다 |
| ‘오늘’의 기준 | 이벤트에 저장할 시간대. `Intl.DateTimeFormat(..., { timeZone })`로 `YYYY-MM-DD`를 구한다 |
| 기존 이벤트 | 날짜가 지나도 조회와 응답 수정이 된다 |
| 시간대 값 | 서버에서 `Intl`로 유효한 IANA 이름인지 검증하고, 아니면 400 |
| 시작·종료 시각 | 선택 간격(15·30·60분) 단위로 선택지를 준다. 종료 24:00 허용, 최소 한 칸 이상 |
| 간격 변경 | 기존 시각이 새 간격에 맞지 않으면 임의로 반올림하지 않는다. 그 입력을 오류로 표시하고 다시 고르게 안내한다 |

- 서버의 시각 범위·간격 배수 검증은 유지하고 회귀 검증한다. 첫 행은 09:15·09:30처럼 정각이 아닌 시작 시각도 표시한다(`Grid.tsx:155`). 15/30분 이벤트의 회의 길이·TF 타임 초기값은 실제 이벤트 범위 안으로 제한한다(`AdminView.tsx:24`의 최소 60분 초기값 보완).
- 자정 전부터 열린 양식도 제출 시점의 서버 날짜로 다시 검사하고 입력을 유지한 채 오류를 안내한다. 오늘 날짜는 허용한다.
- 테스트: 오늘 허용 / 어제 거부(두 모드), 시간대 경계(UTC 15:30 = KST 다음날 00:30), 09:15·09:30 시작, 24:00 종료, 잘못된 시간대 거부.

### 6.2 문구

| 위치 | 문구 |
|---|---|
| 시간 설정 묶음 제목 | `응답받을 시간 범위` |
| 시작 / 종료 / 슬롯 단위 | `시작 시각` / `종료 시각` / `선택 간격` |
| 참가자 비밀번호 입력란 아래 | "비밀번호를 설정하지 않으면 같은 이름으로 접속한 사람이 응답을 수정할 수 있어요." |
| 응답 화면 저장 상태 | `저장됨 · 같은 이름으로 다시 들어오면 수정할 수 있어요` |

비밀번호와 재접속 안내는 **현재 권한 정책**에 맞춘 문구다. 4단계에서 정책이 바뀌면 문구도 함께 바꾼다.

### 6.3 생성 폼 오류 안내와 기준 시간대 (QA a4, b)
- 만들기 버튼이 비활성인 이유를 버튼 위에 한 줄로 보여 준다. 날짜 모드에 이미 있는 안내 방식을 시간 모드에도 맞춘다.
  - 예: "이벤트 이름을 입력하세요" / "날짜를 1개 이상 고르세요" / "종료 시각은 시작 시각보다 늦어야 해요"
  - 여러 개면 첫 번째 이유만 보여 준다.
- 종료 시각 목록은 시작 시각보다 늦은 값만 보여 준다. 시작을 바꿔서 기존 종료 값이 맞지 않게 되면 6.1의 간격 변경 규칙처럼 오류로 표시하고 다시 고르게 한다.
- **기준 시간대**: 생성 화면에 "한국 시간(Asia/Seoul) 기준으로 만들어요"처럼 저장될 시간대를 보여 주고, 바꿀 수 있는 선택 목록을 둔다.
  - 기본값은 브라우저 시간대다. 목록은 자주 쓰는 시간대 몇 개 + 전체 IANA 목록(`Intl.supportedValuesOf("timeZone")`)이다.
  - 해외에 있는 학생이 만들면 그 나라 시간대가 조용히 저장되어 국내 참가자에게 엉뚱한 시간으로 보이는 문제(QA b)를 막기 위한 것이다.
  - 시간대 변경은 입력한 날짜·시각의 기준을 바꾸는 동작임을 안내한다. 입력을 몰래 시차 변환하지 않고 선택한 시간대의 오늘 기준으로 재검증한다. 서버와 화면의 오늘 계산도 같은 선택값을 사용한다.
  - 참가자 현지 시각 변환은 후속이다(9.2절). 날짜 전용 응답의 YYYY-MM-DD는 현지 시각 변환 대상으로 삼지 않는다.

### 6.4 마감 품질 (QA a6, a7, b)
| 항목 | 변경 |
|---|---|
| 404 | `src/app/not-found.tsx` 추가. "일정을 찾을 수 없어요" + 홈 링크. `/e/[id]`에서 이벤트가 없을 때도 이 페이지 |
| 탭 제목 | 이벤트·관리자 페이지에서 `generateMetadata`로 "{일정 이름} · When2meet+" |
| 보안 헤더 | `next.config.ts`의 `headers()`: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`(또는 CSP `frame-ancestors 'none'`), `poweredByHeader: false`. HSTS는 실제 HTTPS 적용 범위와 앞단 정책을 확인한 뒤 적용한다. 전체 CSP는 Next 인라인 스크립트 처리 때문에 따로 검증한 뒤 넣는다 |
| 관리자 링크 표시 | 모바일에서 말줄임 대신 줄바꿈(`overflow-wrap: anywhere`), 복사 버튼 유지 |
| export 기본값 | 시간 모드에서 화면·API의 공통 기본값은 `min(endMin-startMin, max(slotMinutes, 60))`. 화면 다운로드는 현재 선택한 값을 명시한다. 날짜 모드에는 회의 길이를 적용하지 않는다 |
| 날짜 달력 대비 | 날짜 모드 히트맵 색 대비 상향(지금 `--heat * .35`). 2/8처럼 적은 인원도 구분되게. 라이트·다크 모드 모두 확인 |

- 테스트: 없는 이벤트·없는 경로가 한국어 404, 이벤트 탭 제목, 응답 헤더 확인(`curl -I`), 짧은 이벤트를 포함한 API 기본 회의 길이가 화면과 같은지.
- 일반 CSV는 슬롯별 가용 데이터이며 최적 시간 시트가 없다. XLSX 최적 시간·JSON bestTimes·일반 CSV·TF 배분 CSV의 목적을 버튼과 안내에서 구분한다.
- 화면에서 내려받는 XLSX 최적 시간·JSON bestTimes에는 회의 길이·최소 인원·필수 참석자·결과 개수 조건을 전달한다. 현재 `exportQuery`와 `ExportOptions`에는 필수 참석자가 없으므로 경로를 보완한다. 같은 응답 스냅샷·조건의 화면과 파일을 대조한다.
- 직접 API의 생략 기본값 변경은 문서와 변경 내역에 명시한다. QA 관찰은 실제 다운로드 요청 조건을 확인해 재현하며, CSV 슬롯 간격과 회의 길이를 혼동하지 않는다.

## 7. 3단계: 응답 관리

| 기능 | 결과 | 권한 | API |
|---|---|---|---|
| 선택 전체 해제 | 참가자는 남고 "가능한 시간 없음"으로 집계된다 | 본인 토큰 | 기존 `PUT availability`에 `slots: []` |
| 관리자 응답 삭제 | 참가자와 응답을 집계에서 뺀다 | 관리자 키 | `DELETE /api/events/[id]/participants/[pid]` (신규) |

- 확인창에 대상 이름과 결과를 보여 준다. 전체 해제는 현재 날짜 페이지뿐 아니라 이벤트 전체 날짜·시간을 비운다고 안내한다. 삭제는 참가자 집계에서도 빠지고 되돌릴 수 없다고 알린다.
- 성공하면 히트맵과 최적 시간 결과를 갱신한다. 삭제된 사람이 필수 참석자라면 필터와 더 이상 유효하지 않은 상세·강조도 정리한다. 최소 인원은 임의로 낮추지 않고 조건 미충족을 안내한다. 기존 TF 배분안에는 재계산 안내를 띄우고 담당자를 자동으로 바꾸지 않는다.
- 삭제된 참가자의 모든 수정 세션을 무효화한다. 삭제 전에 출발한 자동저장이 늦게 도착해도 참가자가 되살아나지 않아야 한다. 저장은 존재하는 참가자만 조건부 갱신하며, 조회 후 삭제가 일어나도 upsert로 재삽입하지 않는다. 해당 기기는 다음 저장/조회에서 삭제 사실을 안내하고 로컬 세션을 정리한다.
- 화면: 응답 화면 아래에 `선택 전체 해제`(보조 버튼). 관리자 화면 참가자 목록에는 행마다 `삭제`.
- 테스트: 전체 해제는 대상 참가자와 토큰 불일치 시 거부, 관리자 삭제는 관리자 키 누락·불일치 시 거부한다. 삭제 뒤 분석·내보내기에서 제외되고 지연 저장으로 복원되지 않는지 확인한다.

## 8. 4단계: 참가자 권한 개선 (후속 개발안)

사용자가 지적한 외부 참여 편의성과 재접속 비용을 고려해 최초 참여는 이름만으로 유지한다. 아래는 후속 개발 시 적용할 권장 정책이며, 이번 문서 작성에서 구현하지 않는다. 실제 후속 작업의 범위는 해당 사용자 요청을 따른다.

### 8.1 해결할 문제
1. 비밀번호 없는 기존 이름만으로 새 수정 권한을 받을 수 있다.
2. 새 토큰이 기존 토큰을 덮어써서 원래 기기의 저장도 실패한다.

세션을 여러 개 허용하는 것만으로는 1번이 해결되지 않는다.

### 8.2 제안 정책
- 첫 참여는 계속 이름만으로 받는다.
- 기존 이름으로 다시 들어올 때는 셋 중 하나를 확인한다: 기존 기기의 토큰, 개인 수정 링크, 비밀번호.
- 확인된 다른 기기에는 세션을 **추가**하고, 기존 기기의 세션은 유지한다. 지금 저장돼 있는 유효한 토큰은 전환 뒤에도 그대로 쓴다.
- 이름만 입력해서는 기존 응답을 수정하거나 삭제할 수 없다.
- 권한을 모두 잃은 경우에는 관리자가 확인한 뒤 복구하는 경로를 둔다(예: 관리자 화면에서 개인 수정 링크 재발급).
- **본인 참여 취소**(`DELETE /api/events/[id]/participants`, 본인 토큰)는 이 단계에 함께 넣는다. 지금 규칙대로라면 이름만 아는 사람이 남의 참여를 취소할 수 있기 때문이다.
- 6.2의 안내 문구를 새 정책에 맞게 바꾼다.

### 8.3 다중 세션과 저장 충돌
- 여러 기기의 오래된 전체 선택이 서로 덮어쓰지 않도록 응답에 버전을 둔다. 읽은 버전이 현재 서버 버전과 같을 때만 원자적으로 저장한다.
- 충돌하면 서버 응답을 유지하고 해당 기기의 후속 자동저장을 멈춘다. 임시 선택은 보존하고 “다른 기기에서 응답이 변경되었습니다”를 표시한다.
- `최신 응답 불러오기`에서 미저장 변경이 사라짐을 확인한 뒤 최신 응답으로 다시 편집한다. 이번 단계에 자동 병합은 포함하지 않는다.
- 한 기기의 저장 큐도 직전 성공 응답의 최신 버전을 사용한다.
- 정책을 보류한다면 안내와 관리자 삭제까지만 진행한다. 세션 추가만을 자동 적용하는 최소안으로 두지 않고 본인 참여 취소도 노출하지 않는다.

### 8.4 이름 비교 규칙 (QA a8)
- 지금은 앞뒤 공백만 제거하고 대소문자를 구분한다. 그래서 "TEST-A"와 "test-a"가 다른 사람이 된다.
- NFC·대소문자·연속 공백 정규화는 **비슷한 이름 안내용**으로만 사용한다. 저장된 참가자 ID나 로그인 대상 매칭을 조용히 바꾸지 않는다.
- 기존 참가자를 자동 병합하지 않는다. 비슷한 이름이 있으면 기존 응답으로 돌아갈지 또는 구분되는 새 이름으로 참여할지 안내한다. 기존 응답 접근은 반드시 8.2의 권한을 확인한다.
- 이름 매칭 자체를 바꾸는 마이그레이션은 이번 단계의 기본안에서 제외한다.

### 8.5 복구와 이전
- 개인 수정 링크는 기존 수정 권한을 확인해 발급한다. 이름만으로 링크를 받을 수 없다.
- 관리자 확인 후 복구는 기존 세션·링크를 무효화하고 새 링크를 발급하는 별도 동작이다. 정상적인 추가 기기 로그인은 기존 세션을 유지한다.
- 현재 유효한 토큰과 비밀번호를 보존한다. 새 응답 버전 규칙을 지원하지 않는 오래된 화면에는 새로고침을 안내하고 버전 검사 없는 저장을 허용하지 않는다.

## 9. 5단계와 후속 범위

### 9.1 5단계: 접근성과 결과 가독성 (QA a5, b)
- **시간표 키보드·스크린리더 접근**: 칠할 수 있는 시간표에 roving tabindex(칸 하나만 `tabindex=0`)를 둔다. 방향키로 이동하고, Space·Enter로 토글하고, Shift+방향키로 범위를 선택한다. 표 구조 안의 선택 버튼에 `aria-label`("11월 9일 (월) 10:00–10:30, 선택됨")과 `aria-pressed`를 제공한다. 일반 td에 버튼 전용 상태만 붙이지 않는다. 읽기 전용 히트맵도 키보드로 칸의 참여자 정보를 확인할 수 있게 한다. 날짜 모드 버튼 수준으로 맞추는 것이다. 1단계에서 `Grid` 구조가 바뀌므로 그 뒤에 한다.
- **연속 구간 합치기**: 최적 시간 결과에서 같은 인원 구성으로 이어지는 겹치는 구간(예: 10:00–11:00, 10:30–11:30)을 "10:00–11:30 (3/3명)"처럼 하나로 합쳐 보는 옵션을 둔다. 기본은 지금 목록으로 두고, 합치기는 보기 전환으로만 제공한다. export에도 같은 옵션을 넣을지는 구현 때 정한다.

### 9.2 후속 범위 (이번 기획 밖)
- **이벤트 수정·삭제**: 이름 변경과 날짜·시간 범위 변경을 구분한다. 범위를 바꿀 때 기존 응답을 유지할지 뺄지 정책을 정한 뒤 추가한다. 삭제 전 백업(`VACUUM INTO`)도 정한다.
- **참가자 현지 시각 표시**: QA 원본으로 "시간대"가 기준 시간대를 뜻한다는 게 확인됐다. 생성 때 선택하는 기능은 2단계(6.3)에 넣었다. 참가자 화면의 "내 시간대로는 …" 보조 표기는 날짜 경계와 서머타임(QA 미테스트)을 포함해 따로 설계한다. 국내 사용자 위주라 우선순위는 가장 낮다.

### 13.1 두 출처 문서의 차이와 최종 판단

| 주제 | Claude 문서 | GPT 문서 | 최종 판단과 이유 |
|---|---|---|---|
