## 3. 1단계: 모바일 시간표 (시제품)

### 3.1 목표
- 시간표 위에서 스와이프하면 **스크롤**된다.
- 짧게 탭하면 **한 칸**을 켜고 끈다.
- **길게 누른 뒤 끌면** 여러 칸을 칠한다.
- 칸이 손가락으로 정확히 누를 수 있는 크기가 된다.
- PC 마우스 드래그는 바뀌지 않는다.

### 3.2 조작 규칙 (상태 기계)

```
           touchstart (칸 위)
                 │  preventDefault 하지 않음
                 ▼
             [대기 pending] ──── 타이머 전에 touchend, 이동 없음 ───▶ 한 칸 토글 → [idle]
              │        │
   이동 > SLOP 또는     │ LONG_PRESS_MS 동안 이동 ≤ SLOP,
   scroll 이벤트 발생   │ 스크롤도 없음
              ▼        ▼
       [스크롤 scroll]  [칠하기 painting] ── 시작 칸 강조
        손 뗄 때까지     │  touchmove: e.cancelable 이면 preventDefault 후 칠하기
        전환 금지        │           e.cancelable 아니면 → 취소 (원래대로)
              │        │  touchend   → 확정(onChange)
              │        │  touchcancel → 취소 (미리보기 버리고 응답 변경 없음)
              ▼        ▼
            [idle]   [idle]
```

**규칙**
1. `touchstart`에서는 `preventDefault()`를 하지 않는다. 브라우저가 스크롤할 수 있게 둔다.
2. **스크롤로 판정되면 손을 뗄 때까지 칠하기로 바뀌지 않는다.** 판정 근거는 셋 중 하나다.
   - 대기 중에 이동 거리가 `SLOP`을 넘었다.
   - 대기 중에 `.grid-wrap`이나 `window`에서 `scroll` 이벤트가 났다.
   - 칠하기에 들어간 뒤 첫 `touchmove`가 `cancelable === false`다.
3. 이동이 `SLOP`보다 작다고 해서 칠하기로 전환할 수 있다고 **단정하지 않는다**. 이미 스크롤로 넘어간 이동이 있으면 그 뒤에 스크롤을 막을 수 있는지가 브라우저마다 다르다. 그래서 `touchmove`의 `cancelable`을 매번 확인하고, `false`면 칠하기를 버린다.
4. **취소하면 응답은 바뀌지 않는다.** `touchcancel`, 스크롤 판정, `cancelable === false` 모두 미리보기를 버리고 `onChange`를 부르지 않는다. 지금 코드의 "`touchcancel`이면 저장"은 바꾼다.
5. 칠할지 지울지는 기존과 같다. 시작 칸의 상태가 정한다(켜진 칸에서 시작하면 지우기).
6. 처음 값은 `LONG_PRESS_MS = 300`, `SLOP = 10px`로 둔다. **이 값들이 안정성을 보장하지는 않는다.** 상수로 빼 두고 실기기에서 조정한다.

**피드백 표시**
- 칠하기가 시작되면 시작 칸에 테두리와 확대 강조를 넣는다. **진동 없이도 시작을 알 수 있어야 한다.**
- `navigator.vibrate`는 지원하는 환경(안드로이드)에서만 보조로 쓴다. iOS Safari는 지원하지 않는다.
- 대기 중에도 칸을 살짝 눌린 색으로 바꿔서 "누르고 있으면 뭔가 된다"는 걸 보여 준다(선택).

**브라우저 기본 동작 억제**
- 칸에 `touch-action: manipulation`을 준다. 상하좌우 이동은 허용하고, 더블탭 확대는 막는다.
- 기존의 `user-select: none`과 `-webkit-touch-callout: none`은 유지한다. 칸 위에서는 `contextmenu`도 `preventDefault`해서 안드로이드 길게 누르기 메뉴를 막는다.

**안내**
- 손가락이 닿는 기기(`@media (pointer: coarse)`)에서만 시간표 위에 "탭: 한 칸 선택 · 길게 눌러 끌기: 여러 칸 선택"을 보여 준다. 길게 누르기도 화면에 안 보이는 조작이라 안내가 꼭 필요하다.
- 자동저장 상태(`저장 중… / 저장됨`)는 지금처럼 함께 보여 준다.

### 3.3 칠하는 중 화면 끝 자동 스크롤
칠하기 상태에서는 스크롤이 막힌다. 칸을 키우면 시간 범위가 화면 높이를 넘으니, 다음처럼 자동으로 스크롤한다.
- 손가락이 화면 위아래 끝 48px 안에 있으면 `window`를 세로로 스크롤한다.
- 손가락이 `.grid-wrap` 좌우 끝 32px 안에 있으면 `.grid-wrap`을 가로로 스크롤한다.
- `requestAnimationFrame`으로 돌리고, 끝에 가까울수록 빨라지게 한다. 스크롤된 뒤에는 손가락 아래 칸을 다시 계산해서 칠한다.

### 3.4 레이아웃
- **세로**: 표 안에 세로 스크롤을 두지 않는다. 페이지 전체가 길어진다. 결과표가 자연스럽게 세로로 늘어나는 기존 동작도 유지한다.
- **가로**: `.grid-wrap` 안에서만 스크롤한다. 페이지 전체가 옆으로 밀리지는 않는다.
- **칸 크기** (`pointer: coarse`):
  - 높이: 1시간 칸 36px, 30분 칸 28px, 15분 칸 24px (시작값)
  - 최소 너비: 44px. 표는 `width: max-content; min-width: 100%`로 둬서 넘치면 가로 스크롤이 생긴다.
- **시간 열**: 왼쪽에 고정(`position: sticky; left: 0`)하고 배경을 넣는다.
- **날짜 머리글 고정**: `overflow-x: auto` 컨테이너 안에서는 `sticky top`이 화면 기준으로 붙지 않을 수 있다. **따로 검증한다.** 안 붙으면 가로 스크롤과 위치를 맞춘 별도 머리글을 쓸지, 고정을 포기할지 그때 정한다.
- PC(`pointer: fine`)는 지금 크기를 유지한다.

### 3.5 적용 범위
| 화면 | 적용 |
|---|---|
| 참가자 응답 시간표 (`Grid`, 칠하기 가능) | 3.2 ~ 3.4 전부 |
| 날짜 모드 달력 (`DateGrid`, 칠하기 가능) | 3.2 조작 규칙만. 칸이 이미 58px라 크기는 그대로 |
| 히트맵 보기 (`Grid`, 칠하기 불가: 참가자 결과·관리자) | 3.4 레이아웃만. 탭하면 슬롯 상세를 보여 주는 기존 동작 유지 |

### 3.6 구현 메모
- 제스처 판정은 **화면과 분리된 순수 함수(상태 기계)**로 만들어 `Grid`와 `DateGrid`가 같이 쓴다. 예: `src/lib/touch-paint.ts`, 이를 감싸는 훅 `useTouchPaint`. 상태 전이는 `node:test`로 단위 테스트한다(대기→탭, 대기→스크롤, 대기→칠하기, 칠하기→취소, cancelable=false).
- 이벤트 리스너는 지금처럼 non-passive 네이티브 터치 이벤트를 쓴다. 바뀌는 건 `touchstart`에서 막지 않는다는 점과, 칠하기 상태에서만 `touchmove`를 막는다는 점이다.
- 마우스·펜 입력(`pointer*` 이벤트)은 건드리지 않는다.

### 3.7 대안 (검증 실패 시): 선택 모드 버튼
8절 기준을 통과하지 못하면 다음으로 바꾼다. 3.3 ~ 3.5의 레이아웃 작업은 그대로 다시 쓴다.
- 기본 상태: 스와이프하면 스크롤, 탭하면 한 칸.
- `여러 칸 선택` 버튼을 켜면 지금처럼 터치하는 순간 칠하기(기존 iOS 수정 로직 그대로)가 되고, 끄면 스크롤이 된다.
- 버튼은 긴 시간표에서도 닿게 화면 아래 고정 바에 두고, 자동저장 상태를 같이 보여 준다.

## 4. 2단계: 과거 날짜 제한과 안내 문구

### 4.1 과거 날짜 제한 (두 모드)
- **화면**
  - 시간 모드 달력: 지난 날짜를 `disabled`로 만든다(흐리게 표시만 하던 것을 선택 불가로).
  - 날짜 모드: 범위 입력에 `min=오늘`을 넣는다.
- **서버** (`POST /api/events`): `dates` 중 이벤트 시간대 기준으로 오늘보다 이른 날짜가 있으면 400을 돌려준다.
- **오늘 계산**: 이벤트 `timezone`으로 `Intl.DateTimeFormat(..., { timeZone })`을 써서 `YYYY-MM-DD`를 구한다. 화면은 브라우저 시간대(= 저장될 시간대)를 기준으로 한다.
- **새로 만들 때만 적용**한다. 이미 있는 이벤트는 날짜가 지나도 응답과 조회가 그대로 된다.
- 테스트: 오늘은 허용, 어제는 거부, 시간대 경계(예: UTC 15:30 = KST 다음날 00:30).

### 4.2 문구
| 위치 | 현재 | 변경 |
|---|---|---|
| 참가자 비밀번호 입력란 | `비밀번호 (선택 · 이 이벤트에서만 사용)` | 아래에 한 줄 추가: "비밀번호를 설정하지 않으면 같은 이름으로 접속한 사람이 응답을 수정할 수 있어요" |
| 저장 상태 | `저장됨` | `저장됨 · 같은 이름으로 다시 들어오면 수정할 수 있어요` |
| 만들기 화면 시간 설정 | 시작 / 종료 / 칸 단위 | `응답받을 시간 범위` 아래 `시작 시각` · `종료 시각` · `선택 간격` |
| 이벤트 화면 머리말 | `Asia/Seoul 기준` | `한국 시간(Asia/Seoul) 기준`처럼 읽기 쉬운 이름 (선택) |

안내 문구가 있어도 무단 수정은 그대로 가능하다. 실제로 막는 건 6단계에서 다룬다.

## 5. 3단계: 30분 단위 시작·종료 시각
- `선택 간격`이 15분이나 30분이면 시작·종료 시각을 30분 단위로 고를 수 있게 한다. 1시간이면 정각만이다.
- 서버는 이미 `startMin % slotMinutes`를 검사하니 바꿀 필요가 없다. 화면 선택지만 바꾼다.
- 간격을 바꿔서 기존 선택이 맞지 않게 되면, 가장 가까운 유효한 값으로 맞춘다.

## 6. 4단계: 응답 삭제·관리
| 기능 | 동작 | 권한 | API |
|---|---|---|---|
| 선택 전체 해제 | `slots = []`. 참가자는 남고 "가능한 시간 없음"으로 집계된다. | 본인 토큰 | 기존 `PUT availability` 재사용 |
| 참여 취소 | 참가자 행을 삭제해 집계에서 빠진다. localStorage 세션도 지운다. | 본인 토큰 | `DELETE /api/events/[id]/participants` (participantId + token) |
| 관리자 응답 삭제 | 장난·중복 응답 삭제 | 관리자 키 | `DELETE /api/events/[id]/participants/[pid]` (admin key) |

- 둘 다 확인 대화상자를 띄운다. 참여 취소는 되돌릴 수 없다고 알린다.
- 화면: 응답 화면 아래에 `선택 전체 해제`(보조 버튼)와 `참여 취소`(위험 버튼)를 나눠서 둔다. 관리자 화면 참가자 목록에는 행마다 삭제를 둔다.
- 테스트: 토큰이 틀리면 401, 관리자 키가 틀리면 403, 삭제한 뒤 분석과 내보내기에서 빠지는지.

## 7. 5단계: 정책 결정이 필요한 항목 (보류)

### 7.1 수정 권한 / 토큰 재발급
- **현재 문제**: 비밀번호가 없는 기존 이름이면 누구에게나 토큰을 재발급하고 원래 세션을 덮어쓴다.
- **선택지**
  - (a) 덮어쓰지 않고 세션을 **추가**한다(여러 기기 허용). 원래 기기가 튕기는 문제만 해결되고, 무단 수정은 여전히 가능하다.
  - (b) 비밀번호가 없는 기존 이름은 **이미 토큰이 있는 기기나 개인 수정 링크로만** 수정할 수 있게 한다. 첫 참여는 지금처럼 이름만으로 받는다. 다른 기기로 복귀하기 어렵다는 불편이 생기는데, 관리자 링크 재발급이나 수정 링크 복사 안내로 보완한다.
  - (c) 지금처럼 둔다(웬투밋과 같음).
- 홈페이지 통합 때 회원 체계와 함께 정한다. 그전에 (a)만 먼저 해도 부작용이 거의 없다.

### 7.2 이벤트 수정·삭제
- 날짜나 시간 범위를 바꾸면, 범위 밖으로 나간 기존 응답 슬롯을 지울지, 숨길지, 막을지 정해야 한다.
- 이벤트 삭제는 관리자 키로 하고, 삭제 전 백업(dbadmin의 `VACUUM INTO` 방식)을 할지 정해야 한다.

### 7.3 기준 시간대
- **테스터에게 확인할 것**: "시간대"가 ① 시작·종료 시각(3단계로 해결)을 뜻했는지, ② 한국·미국 같은 기준 시간대를 뜻했는지.
- ②라면 만들기 화면에 시간대 선택을 넣고(기본값은 브라우저), 참가자가 자기 시간대로 바꿔 보는 기능은 별도로 판단한다. 국내 사용자가 대부분이라 우선순위는 가장 낮다.

## 8. 1단계 채택 기준과 검증

### 8.1 필수 기준 (하나라도 실패하면 3.7 대안으로 전환)
1. 칸 위에서 시작한 빠른 세로·가로 스와이프는 **스크롤만 되고 칸은 바뀌지 않는다**.
2. 스크롤로 판정된 동작은 손을 뗄 때까지 **칠하기로 바뀌지 않는다**.
3. 스크롤, `touchcancel`, 중간 취소가 일어나도 **응답이 바뀌지 않는다**(서버 저장 요청이 나가지 않는다).
4. **iOS Safari**에서 길게 누른 뒤 첫 칸부터 마지막 칸까지 끌면, 지나간 칸이 전부 저장된다. 새로고침 뒤에도 남아 있어야 한다.
5. 진동 없이도 칠하기 시작을 화면으로 알 수 있다.
6. 짧은 탭은 한 칸만 바꾼다.
7. PC 마우스 드래그는 이전과 똑같이 동작한다.
8. 320px 화면에서 페이지 전체가 가로로 넘치지 않는다.

### 8.2 확인 항목 (실패해도 전환 사유는 아님, 개선 대상)
- 칠하는 중 화면 끝 자동 스크롤이 자연스러운지
- 날짜 머리글 고정이 되는지
- 안드로이드에서 길게 누르기 메뉴나 문자 선택이 뜨지 않는지
- 기대 시간이 너무 길거나 짧다는 느낌이 없는지

### 8.3 기기
| 필수 | 가능하면 |
|---|---|
| iPhone Safari (iOS 최신) | iPhone Chrome (같은 WebKit 엔진) |
| Android Chrome | Samsung Internet |
| PC Chrome / Safari (회귀 확인) | iPad Safari |

### 8.4 검증 시나리오
| # | 동작 | 기대 결과 |
|---|---|---|
| S1 | 칸 위에서 빠르게 위로 스와이프 | 페이지 스크롤, 칸 변화 없음, 저장 요청 없음 |
| S2 | 칸 위에서 빠르게 옆으로 스와이프 (날짜가 많은 이벤트) | 시간표 가로 스크롤, 칸 변화 없음 |
| S3 | 칸 짧게 탭 | 그 칸만 켜짐/꺼짐, 저장됨 |
| S4 | 빈 칸 길게 누르기 → 아래로 5칸 끌기 → 떼기 | 강조 표시 후 6칸 켜짐, 저장, 새로고침 뒤에도 유지 |
| S5 | 켜진 칸 길게 누르기 → 끌기 | 지나간 칸 꺼짐 |
| S6 | 누른 채 3–9px 흔들다 그대로 기다리기 | 칠하기로 들어가거나 아무 일도 없음. **어느 쪽이든 스크롤과 칠하기가 동시에 일어나지 않음** |
| S7 | 스크롤 도중 멈추고 계속 누르고 있기 | 칠하기로 바뀌지 않음 |
| S8 | 칠하는 중 화면 아래 끝으로 끌기 | 자동 스크롤되며 계속 칠해짐 |
| S9 | 칠하는 중 알림·전화 등으로 `touchcancel` | 미리보기 사라짐, 응답 변화 없음 |
| S10 | 두 손가락으로 확대·축소 | 칠하기 없음 |
| S11 | 날짜 모드 달력에서 S1·S4 | 같은 결과 |
| S12 | PC에서 마우스 드래그 | 이전과 같음 |

## 9. 진행 순서
1. **1단계 시제품**: 상태 기계와 단위 테스트 → `Grid` 적용 → 레이아웃 → 자동 스크롤 → `DateGrid` 적용
