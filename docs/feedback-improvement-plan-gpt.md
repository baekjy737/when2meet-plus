# When2meet+ 테스트 피드백 통합 개선 기획서

- 작성일: 2026-11-02
- 상태: 기획 완료 · 구현 전
- 근거: 사용자 피드백, 사용자 답변, Claude·GPT 상호 검토 및 코드 확인
- 기본 방향: 모바일 선택 모드 버튼 + 날짜 나눠 보기 + 칸 크기 확대 + 선택 중 자동 스크롤
- 작업 방식: 기능별 브랜치에서 검증 후 main 대상 PR 생성. 자동으로 머지하지 않는다.

이 문서는 대화에서 마지막으로 정리한 통합 기획안이다. 모바일은 명시적인 선택 모드 버튼을 기본으로 하고, 시간표의 날짜 열은 표시 너비에 맞춰 나눠 보여준다.

## 1. 목표와 범위

1. 모바일에서 시간표를 스크롤하다 응답이 바뀌는 문제를 해결한다.
2. 날짜 수와 관계없이 누르기 쉬운 칸 크기를 확보한다.
3. 긴 시간 범위를 한 번의 드래그로 선택할 수 있게 한다.
4. 이벤트 생성 시 날짜·시간 입력 규칙을 명확하게 한다.
5. 응답 수정, 전체 해제, 참여 취소, 관리자 삭제를 구분한다.
6. 재접속 시 수정 권한과 기존 기기 세션을 보호한다.

이벤트 설정 수정·삭제와 기준 시간대 선택·변환은 후속 범위로 둔다. 이번 기획서 저장은 구현이나 배포를 의미하지 않는다.

## 2. 모바일 입력 방식

### 2.1 상태별 동작

| 상태 | 탭 | 손가락으로 밀기 | 표시 |
|---|---|---|---|
| 기본 | 한 칸 선택·해제 | 페이지 스크롤 | `여러 칸 선택` |
| 여러 칸 선택 | 한 칸 선택·해제 | 여러 칸 선택·해제 | `선택 완료` + 선택 중 표시 |
| 읽기 전용 히트맵 | 해당 칸의 참여자 표시 | 페이지 스크롤 | 선택 버튼 없음 |

- 선택한 칸에서 드래그를 시작하면 해당 범위를 해제한다.
- 변경 내용은 탭 또는 드래그를 마칠 때 자동 저장한다.
- `선택 완료`는 선택 모드를 종료하는 버튼이다. 저장 버튼으로 오해하지 않도록 “변경 내용 자동 저장”을 함께 표시한다.
- 기본 상태에서 스크롤을 시작한 손동작은 손을 뗄 때까지 선택으로 바뀌지 않는다.
- 터치를 시작했다는 이유만으로 응답을 변경하지 않는다.

### 2.2 버튼과 입력 장치

- 선택 버튼과 상태 안내는 편집 영역을 보고 있는 동안 화면 위쪽에서 접근할 수 있게 배치한다.
- 도구가 시간표를 과도하게 가리지 않도록 한다.
- PC 마우스 드래그는 선택 모드와 무관하게 기존처럼 바로 동작한다.
- 터치와 마우스를 함께 쓰는 기기도 지원한다.
- `pointer: coarse`만으로 버튼 표시 여부를 결정하지 않는다. `any-pointer: coarse` 등 터치 입력 가능 여부도 고려한다.

참고: [MDN — any-pointer](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/any-pointer)

## 3. 칸 크기와 날짜 나눠 보기

### 3.1 표시 규칙

| 대상 | 표시 규칙 |
|---|---|
| 터치 환경의 시간표 | 날짜 열 최소 너비 56px, 시간 칸 최소 높이 32px를 초기값으로 적용 |
| 한 화면의 날짜 수 | 실제 표 너비에서 시간 열·여백을 제외한 공간으로 계산 |
| 날짜 이동 | `이전 날짜` / `다음 날짜`, 현재 날짜 범위와 전체 날짜 수 표시 |
| 날짜 조율 모드 | 기존 월별 7열 달력 유지 |
| 관리자·참가자 전체 히트맵 | 시간표와 동일한 날짜 나눠 보기 적용 |

- 15분 단위에서도 시간 칸 높이를 절반으로 줄이지 않는다.
- 표시 가능한 날짜 수는 기기 화면 너비가 아닌 실제 표의 가용 너비로 계산한다.
- 첫 페이지와 마지막 페이지에서는 해당 방향 이동 버튼을 비활성화한다.
- 날짜 달력에는 시간표의 56px 최소 너비를 그대로 적용하지 않는다. 7열이 화면에 들어오도록 여백과 반복 문구를 조정한다.
- 크기 초깃값은 실기기에서 터치 정확도와 화면 사용성을 확인한 뒤 조정할 수 있다.

### 3.2 선택 유지와 화면 전환

- 날짜를 넘겨도 보이지 않는 날짜의 선택까지 모두 유지한다.
- 화면 회전이나 크기 변경으로 표시 개수가 바뀌면, 보고 있던 날짜가 계속 화면 안에 남도록 한다.
- 드래그 중에는 날짜 페이지를 자동으로 넘기지 않는다. 손을 뗀 뒤 이동한다.
- 관리자 결과표에서 날짜·시간을 누르면 해당 날짜가 있는 히트맵 페이지로 이동한 뒤 강조한다.
- 읽기 전용 히트맵에는 선택 모드 버튼과 선택 중 자동 스크롤을 제공하지 않는다.

### 3.3 스크롤 구조

- 시간표와 결과표의 세로 길이는 내용에 따라 늘어난다.
- 내부 세로 스크롤이나 페이지 전체의 가로 넘침은 만들지 않는다.
- 결과표는 기존 요구대로 결과 행 수만큼 자연스럽게 길어진다.

## 4. 선택 중 화면 끝 자동 스크롤

### 4.1 시작 조건

- 실제로 칠하는 중에만 작동한다.
- 기본 상태, 단순 탭, 읽기 전용 히트맵에서는 작동하지 않는다.
- 손가락이 화면 위·아래 가장자리 약 40px 안에 들어오면 페이지를 천천히 이동한다.
- 가장자리에 가까워질수록 속도가 증가하되 상한을 둔다.
- 가장자리 범위와 속도는 실기기 검증 후 조정한다.

### 4.2 선택과 스크롤의 연결

- 화면이 움직이는 동안 손가락 아래 칸을 계속 계산해 선택을 이어간다.
- 손가락이 멈춰 있어도 스크롤로 칸이 이동하면 선택을 갱신한다.
- 현재 편집 중인 표 안에서만 동작한다. 다른 히트맵이나 아래 콘텐츠를 칠하지 않는다.
- 표의 처음이나 끝에 도달하면 해당 방향의 자동 스크롤을 멈춘다.

### 4.3 종료와 취소

다음 상황에서는 즉시 자동 스크롤을 멈춘다.

- 손을 뗐을 때
- 실제 터치 취소가 발생했을 때
- 두 번째 손가락이 닿았을 때
- 화면을 이탈했을 때
- 선택 모드를 종료했을 때
- 날짜 페이지를 변경했을 때

정상적으로 손을 떼면 마지막 칸까지 저장한다. 실제 터치 취소 시에는 이번 드래그 시작 전 상태로 복귀하며, 이전에 완료한 선택은 유지한다.

### 4.4 기존 모바일 수정 유지

- `59e5108`, `dbd364f`의 모바일 수정 사항을 유지하면서 선택 모드에서만 해당 터치 처리를 활성화한다.
- 터치에서 파생된 `pointercancel`과 실제 터치 취소를 구분한다.
- 탭과 호환 클릭이 중복 처리되지 않도록 한다.
- 드래그 종료 시 렌더링 시점과 무관하게 마지막 칸까지 저장한다.

## 5. 이벤트 생성 규칙과 안내

### 5.1 날짜·시간 입력

| 항목 | 동작 |
|---|---|
| 과거 날짜 | 새 이벤트 생성 시에만 제한 |
| 적용 범위 | 시간 조율·날짜 조율 모두 |
| 검증 위치 | 화면과 서버 모두 |
| ‘오늘’의 기준 | 이벤트에 저장할 기준 시간대 |
| 과거 날짜가 섞인 요청 | 날짜를 임의로 빼지 않고 오류 안내 |
| 기존 이벤트 | 날짜가 지나도 조회·응답 수정 가능 |
| 시작·종료 시각 | 선택 간격에 맞춰 15·30·60분 단위로 제공 |
| 종료 시각 | `24:00` 허용, 최소 한 칸 이상의 범위 필요 |

- 선택 간격이 30분이면 `09:00`, `09:30`, `10:00`을 시작 시각으로 선택할 수 있다.
- 선택 간격이 15분이면 `09:15`처럼 15분 단위 시각을 선택할 수 있다.
- 간격을 바꿨을 때 기존 시각이 새 간격에 맞지 않으면 임의로 반올림하지 않고 재선택을 안내한다.
- 잘못된 시간대 값은 서버에서 검증한다.
- 생성 요청 시점에도 서버가 날짜를 다시 검사한다.

### 5.2 문구

| 위치 | 문구 |
|---|---|
| 시간 설정 영역 | `응답받을 시간 범위` |
| 시작 입력 | `시작 시각` |
| 종료 입력 | `종료 시각` |
| 슬롯 단위 입력 | `선택 간격` |
| 비밀번호 입력란 | “비밀번호를 설정하지 않으면 같은 이름으로 접속한 사람이 응답을 수정할 수 있어요.” |
| 응답 화면 | 자동저장 상태와 재접속 수정 안내를 함께 표시 |

비밀번호와 재접속 안내는 현재 권한 정책에 맞춘다. 권한 정책을 변경하는 단계에서는 관련 문구도 함께 변경한다.

## 6. 응답 관리

### 6.1 기능별 의미와 권한

| 기능 | 결과 | 사용할 수 있는 사람 |
|---|---|---|
| 선택 전체 해제 | 참가자는 남고 가능한 날짜·시간만 비워짐 | 해당 참가자 |
| 참여 취소 | 본인 응답과 참가자 집계에서 제거 | 해당 참가자 |
| 관리자 응답 삭제 | 선택한 참가자와 응답을 집계에서 제거 | 이벤트 관리자 |

전체 해제는 “가능한 시간이 없음”이라는 응답으로 남는다. 참여 취소와 관리자 삭제는 인원수에서도 빠진다.

### 6.2 삭제 처리

- 참여 취소·관리자 삭제 시 대상 이름과 삭제 결과를 확인창에 표시한다.
- 성공하면 히트맵과 최적 시간 결과를 갱신한다.
- 이미 생성한 TF 배분안에는 “응답이 변경되었습니다. 다시 계산해 주세요.”를 표시한다.
- TF 담당자를 자동으로 바꾸지는 않는다.
- 삭제된 참가자의 수정 권한은 무효화한다.
- 삭제 전에 시작된 자동저장이 뒤늦게 도착해 참가자를 되살리는 일이 없어야 한다.

관리자 응답 삭제는 관리자 키로 보호해 먼저 제공할 수 있다. 본인 참여 취소는 아래 수정 권한 정책 개선과 같은 단계에 제공한다.

## 7. 수정 권한과 세션 정책

### 7.1 해결할 문제

1. 비밀번호가 없는 기존 이름만으로 다른 사람의 새 수정 권한을 받을 수 있다.
2. 새 토큰이 기존 토큰을 덮어써 원래 기기의 저장도 실패한다.

세션을 여러 개 허용하는 것만으로는 첫 번째 문제가 해결되지 않는다. 현재도 토큰 저장과 응답 저장 시 검증은 구현되어 있으므로, 개선 대상은 새 세션 발급 규칙과 기존 세션 유지 방식이다.

### 7.2 개선 정책

- 최초 참여는 계속 이름만으로 가능하게 한다.
- 기존 참가자로 다시 들어올 때는 기존 기기의 수정 권한, 개인 수정 링크, 비밀번호 중 하나를 확인한다.
- 확인된 다른 기기의 접속에는 새 세션을 추가하고 기존 기기의 세션을 유지한다.
- 기존 사용자에게 저장된 유효한 토큰은 전환 후에도 유지한다.
- 동일한 이름만 입력해서 기존 응답을 수정하거나 삭제할 수 없게 한다.
- 수정 권한을 모두 잃었을 때는 관리자 확인 후 복구하는 경로를 마련한다.
- 권한 정책 변경과 함께 비밀번호·재접속 안내 문구를 수정한다.

## 8. 개발 단계와 PR 범위

| 순서 | 개발 단위 | 포함 범위 |
|---|---|---|
| 1 | 모바일 입력 개선 | 선택 모드, 칸 크기, 날짜 나눠 보기, 자동 스크롤, 히트맵 연동 |
| 2 | 이벤트 생성 개선 | 과거 날짜 제한, 분 단위 시작·종료, 시간 범위·비밀번호·저장 안내 |
| 3 | 응답 관리 | 선택 전체 해제, 관리자 응답 삭제, 삭제 후 집계 갱신 |
| 4 | 참가자 권한 개선 | 재접속 확인, 기존 세션 유지, 복구 경로, 본인 참여 취소 |
| 후속 | 이벤트 설정·시간대 | 이벤트 수정·삭제, 기준 시간대 선택, 참가자 현지 시각 표시 |

- 각 개발 단위는 별도 브랜치에서 작업한다.
- 관련 검증을 마친 뒤 커밋·푸시하고 main 대상 PR을 생성한다.
- 자동으로 머지하지 않는다.
- 단계별로 이미 구현된 기능과 계획된 기능을 구분해 기록한다.

### 후속 설계 사항

- 이벤트 이름 변경과 날짜·시간 범위 변경을 구분한다.
- 날짜·시간 범위 변경 시 기존 응답을 얼마나 유지하고 제외할지 정책을 정한 뒤 추가한다.
- 시간대 기능은 날짜 경계와 서머타임을 포함해 별도로 설계한다.

## 9. 완료 기준

| 검증 영역 | 통과 조건 |
|---|---|
