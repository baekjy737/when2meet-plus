# When2meet+

[When2meet](https://www.when2meet.com)에서 영감을 받은 그룹 일정 조율 웹앱입니다. When2meet 자체는 오픈소스가 아니며, 이 프로젝트는 독립적으로 새로 작성되었습니다.

**When2meet과 다른 점:** 이벤트를 만든 사람은 **최적 시간 순위**를 보고, 결과를 **엑셀(.xlsx) · CSV · JSON API**로 가져갈 수 있습니다.

## 기능

- 날짜와 기준 시간대, 선택 간격(15/30/60분)을 골라 이벤트 생성 (회원가입 없음). 09:15·09:30 시작과 24:00 종료를 지원하며, 새 일정의 과거 날짜는 선택한 시간대 기준으로 차단합니다.
- **날짜 조율** 모드: 시작일~종료일 범위(양끝 포함, 최대 62일)를 정하고, 참가자는 가능한 날짜를 누르거나 드래그해 선택합니다. 이미 선택한 날짜에서 드래그를 시작하면 해당 구간을 해제합니다. 모바일 터치 드래그도 지원하며, 시간 입력 없이 날짜별 히트맵·최적 날짜 순위·내보내기를 제공합니다.
- 참가자: 처음에는 이름(+선택 비밀번호)으로 참여합니다. 같은 브라우저에서는 자동 복원되고, 다른 기기에서는 비밀번호 또는 개인 수정 링크가 필요합니다. 이름만으로 기존 응답을 수정할 수 없습니다.
- 모바일은 기본 탭으로 한 칸을 선택하고 스와이프로 페이지를 스크롤합니다. **여러 칸 선택**을 켜면 드래그와 화면 끝 자동 스크롤로 범위를 선택합니다. 마우스·펜은 바로 드래그할 수 있습니다.
- 시간표 날짜는 화면 너비에 맞춰 나눠 표시합니다. 다른 페이지의 선택도 유지하며, 결과표와 시간표에 내부 스크롤을 두지 않습니다. 키보드 방향키·Enter/Space·Shift+방향키도 지원합니다.
- 선택 전체 해제, 본인 참여 취소, 개인 수정 링크 발급을 지원합니다. 여러 기기의 저장이 충돌하면 덮어쓰지 않고 최신 응답을 다시 불러오도록 안내합니다.
- 그룹 히트맵, 칸에 마우스를 올리면 가능·불가 인원 표시, 10초마다 자동 갱신
- **관리자 페이지** (생성 시 발급되는 비밀 링크)
  - 최적 시간 순위: 회의 길이, 최소 인원, 필수 참석자 필터와 같은 참석자의 연속 구간 묶기
  - 참가자 응답 삭제와 수정 권한 재발급. 재발급 시 이전 세션·수정 링크를 모두 무효화합니다.
  - **TF 시간 배분**: 시간 조율 이벤트에서 타임 길이와 타임당 최소 인원을 설정해 담당자 배분안 생성
  - 엑셀 내보내기: `최적 시간` / `시간대별`(히트맵 색상 포함) / `매트릭스`(참가자×슬롯 0/1) 시트
  - CSV (Excel에서 한글이 깨지지 않도록 BOM 포함), JSON

## TF 시간 배분

시간 조율 이벤트의 관리자 화면에서 **TF 시간 배분** 탭을 선택합니다. 타임 길이(이벤트의 슬롯 단위 배수)와 타임당 최소 인원을 입력하면, 날짜별 시작 시각부터 겹치지 않는 타임으로 나누어 담당자를 제안합니다.

- 각 타임 전체에 가능한 사람만 배정하며, 동일인은 여러 타임에 참여할 수 있습니다.
- 타임마다 설정한 최소 인원만큼 배정하고, 참가자별 배정 횟수가 가능한 한 고르게 되도록 조정합니다. 가용 시간이 다르면 배정 횟수에도 차이가 생길 수 있습니다.
- 인원이 모자라는 타임은 가능한 사람을 배정한 뒤 부족 인원을 표시합니다. 마지막에 타임 길이보다 짧게 남은 시간은 미배정 잔여 시간으로 표시합니다.
- 결과를 시간순으로 보고, 개인별 배정 횟수·총 시간을 확인하거나 **TF 배분 CSV**로 내려받을 수 있습니다. 기존 가용 시간 데이터 내보내기와는 별개입니다.
- 생성한 결과는 현재 화면의 배분안입니다. 참가자 응답이나 설정이 바뀌면 안내에 따라 다시 계산하며, 응답 갱신만으로 담당자를 자동 변경하지 않습니다.

배분은 가용 인원이 적은 타임부터 시작하고, 배정 횟수가 많은 사람의 담당 타임을 가능한 다른 사람에게 옮겨 편차를 줄입니다. 큰 이벤트에서는 추가 균등화 계산을 제한할 수 있으며, 이 경우 화면에 안내합니다.

## 데이터 API

관리자 키를 Bearer 토큰으로 사용합니다.

```bash
curl -H "Authorization: Bearer <ADMIN_KEY>" \
  "https://<host>/api/events/<EVENT_ID>/export?format=json&duration=60&minPeople=3"
```

| 파라미터 | 설명 |
| --- | --- |
| `format` | `json`(기본) · `csv` · `xlsx` |
| `duration` | 회의 길이(분). 선택 간격의 배수이며 이벤트 시간 범위 이내여야 합니다. 생략 시 `min(하루 시간 범위, max(선택 간격, 60))`분입니다. 이 길이 동안 **계속** 가능한 사람만 집계합니다 |
| `minPeople` | 최소 가능 인원 |
| `limit` | 최적 결과 개수 (json·xlsx 기본 20, 최대 10000). 화면 다운로드는 20을 명시합니다 |
| `required` | 필수 참석자의 정확한 이름. 여러 명은 `required=이름1&required=이름2`처럼 반복합니다 |
| `merge` | `1`이면 같은 참석자가 가능한 겹치거나 이어진 시간 후보를 합친 후 limit을 적용합니다 |

화면과 엑셀·JSON의 최적 결과에는 동일한 필터를 전달합니다. CSV는 필터로 잘라낸 최적 결과가 아니라 전체 슬롯별 응답입니다. 직접 API 호출의 기본 회의 길이는 기존 1슬롯에서 위 공통 기본값으로 변경되었습니다.

JSON 응답에는 `event`, `participants`, `bestTimes`, `slots`(슬롯별 가능·불가 명단)가 들어 있습니다.

날짜 모드에서는 `event.mode`가 `date`이고, 참가자의 `slots`는 `2026-11-02` 같은 날짜 문자열입니다. `bestTimes`는 가능한 인원이 많은 날짜 순위이며, `duration`은 적용하지 않습니다. 날짜 모드 JSON에는 시각 필드를 넣지 않고, CSV·엑셀에서도 날짜와 가능·불가 인원만 표시합니다. 시간 모드는 기존 `YYYY-MM-DDTHH:MM` 슬롯 형식을 유지합니다.

이벤트 생성 API(`POST /api/events`)는 `mode: "time" | "date"`를 받으며, 생략하면 기존과 같이 시간 모드입니다. 날짜 모드는 `dates`에 선택 범위의 날짜 배열을 보내면 됩니다. 서버가 날짜 모드의 시간 관련 저장값을 자동 설정하므로 별도 시각 입력은 필요 없습니다.

## 참가자 수정 권한과 저장 API

- `POST /api/events/<id>/participants`: 처음에는 `{name, password?}`. 기존 응답은 비밀번호, 기존 참가자 토큰 또는 `{participantId, editKey}`로 인증합니다. 응답에 `participantId`, `name`, `token`, `slots`, `revision`이 포함됩니다.
- `GET /api/events/<id>/availability?participantId=<pid>`: 해당 참가자 토큰을 Bearer로 보내 현재 `slots`, `revision`, `name`을 읽습니다.
- `PUT /api/events/<id>/availability`: `{participantId, token, slots, revision}`으로 전체 선택을 저장합니다. 성공 시 새 revision을 사용하고, `409 REVISION_CONFLICT`이면 최신 응답을 확인해야 합니다. revision 누락은 `428 REFRESH_REQUIRED`입니다.
- `POST /api/events/<id>/participants/<pid>/edit-link`: 본인 Bearer 토큰으로 개인 수정 키를 발급합니다. 이전 개인 링크는 만료되지만 다른 기기의 세션은 유지합니다.
- `POST /api/events/<id>/participants/<pid>/recovery`: 관리자 Bearer 키로 복구합니다. 모든 기존 세션과 개인 링크를 무효화하고 새 수정 키를 반환합니다. 설정한 비밀번호는 유지합니다.
- `DELETE /api/events/<id>/participants/<pid>`: 본인 또는 관리자 Bearer 권한으로 참가자와 모든 응답·세션을 삭제합니다.

개인 수정 링크는 `/e/<id>#participant=<pid>&edit=<editKey>`입니다. 권한을 담은 비밀 링크이므로 본인만 보관하세요. 이름은 기존처럼 앞뒤 공백만 제거해 비교하며 대소문자·유니코드 표기를 임의로 합치지 않습니다.

## 실행

Node.js 22.13 이상이 필요합니다(내장 `node:sqlite` 사용).

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # 분석 로직 단위 테스트
```

### 내 서버에 배포 (Docker)

```bash
docker compose up -d --build
```

SQLite 파일은 `./data/when2meet.db`에 저장됩니다. HTTPS는 앞단 리버스 프록시(Caddy, nginx 등)에서 처리하세요.

기존 SQLite DB를 사용할 수 있습니다. 첫 실행 때 이벤트 `mode`, 참가자 `revision`·수정 키, 다중 세션 테이블을 트랜잭션으로 이전합니다. 기존 응답과 마지막 유효 토큰은 유지하며, 이전 토큰 가져오기는 일회만 실행해 취소한 권한이 재시작 후 살아나지 않게 합니다. 배포 전 DB 백업을 권장합니다. 예전 페이지를 열어 둔 참가자는 새로고침해야 revision을 포함해 저장할 수 있습니다. DB를 유지한 채 구버전 서버로 되돌리는 것은 새로운 권한 정책과 호환되지 않습니다.

## 구조

```
src/
  app/                 Next.js App Router 페이지 + API 라우트
  components/          Grid(시간), DateGrid(날짜 드래그/히트맵), EventView, AdminView
  lib/analysis.ts      최적 시간 계산 (순수 함수, 클라이언트/서버 공용)
  lib/allocation.ts    TF 타임별 인원 배분과 개인별 집계
  lib/allocation-export.ts  TF 배분안 CSV 생성
  lib/export.ts        xlsx / csv / json 생성
  lib/store/           저장소 인터페이스 + SQLite 구현
```

### Vercel + Firebase로 확장할 때

- `src/lib/store/index.ts`의 `EventStore` 인터페이스를 Firestore로 구현하고, `getStore()`에서 환경변수로 선택하게 하면 됩니다. 나머지 코드는 바꿀 필요가 없습니다.
- 관리자 비밀 링크 대신 로그인 기반 권한으로 바꾸려면 `isAdmin()`(`src/lib/server.ts`)을 교체하면 됩니다.

## 참고

- 시간은 이벤트 생성 시 선택한 기준 시간대(예: `Asia/Seoul`) 기준으로 표시되며, 참가자별 시간대 변환은 하지 않습니다.
- 그룹 가용 시간은 When2meet과 마찬가지로 링크를 가진 누구나 볼 수 있습니다. 내보내기·응답 관리에는 관리자 키가 필요하며, 개인 응답 수정에는 해당 참가자의 수정 권한이 필요합니다.

## DB 관리 페이지 (운영자용)

`ops/dbadmin.mjs`는 의존성 없는 작은 관리 서버입니다. 이벤트 목록과 참가자 상세를 보고, 관리자 링크를 재발급하고, 이벤트나 응답을 삭제할 수 있습니다. 삭제하기 전에는 `VACUUM INTO`로 자동 백업합니다. 임의 SQL은 실행할 수 없습니다.

```bash
DATABASE_PATH=./data/when2meet.db PUBLIC_URL=https://your.host npm run dbadmin   # 127.0.0.1:3101
```

**인증이 없으므로 localhost에만 바인드합니다.** 원격에서 쓰려면 Tailscale `serve`(tailnet 전용) 같은 사설 경로로만 노출하세요. Funnel이나 공개 프록시로는 절대 노출하지 마세요.
